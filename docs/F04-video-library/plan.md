# Implementation Plan: F04. Video Library

**Prerequisites:**
- F02 (Authentication System) and F03 (Video Upload) implemented and merged — this feature builds on the session/bearer-token plumbing and the `Video` aggregate, storage gateway, and upload UI they deliver
- The small synthetic fixture `video-samples/tiny-valid.mp4` (already generated by F03) available for automated tests

### Stage 1: Domain Extensions

**1. Video Rename and Description Rules** - Add `VideoTitle` and `VideoDescription` value objects encoding the 1–200 and ≤2000 character bounds, and add `rename`/`updateDescription` methods to the `Video` entity, per the spec's Component Overview.

**2. Video Deletion Support** - Add a `delete` operation to the `VideoRepository` interface and its Prisma and in-memory implementations, per the spec's Data Model.

**3. Library View Mode Preference** - Add the `libraryViewMode` field and its migration to the `User` model, plus a `LibraryViewMode` value object and a `changeLibraryViewMode` method on the `User` entity, per the spec's Data Model.

### Stage 2: Backend Use Cases and HTTP API

**4. Rename and Description Use Cases** - Implement `RenameVideoUseCase` and `UpdateVideoDescriptionUseCase`, each ownership-checked against the caller.

**5. Delete Video Use Case** - Implement `DeleteVideoUseCase`: remove the persisted row, then best-effort remove the stored video file and thumbnail file, per the spec's Technical Decisions on deletion semantics.

**6. List Videos Sorting** - Extend `ListVideosUseCase` and `VideoQueries` to accept and apply a sort option (`recent`, `oldest`, `title`).

**7. Library View Mode Use Case and Profile Extension** - Implement `SetLibraryViewModeUseCase`, and extend `GetCurrentUserUseCase`'s output to include the current `libraryViewMode`.

**8. HTTP Handlers, Routes, and Composition Root Wiring** - Implement the `PATCH`/`DELETE /videos/:id` handlers, the `sort` query parameter on the list handler, the `PATCH /auth/me/library-view-mode` handler, and register every route and use case in `apps/backend/src/main.ts`.

### Stage 3: Frontend Library Experience

**9. Grid/List Rendering and View Toggle** - Rework the video list component to render either the grid or the compact list layout based on the current view mode, and build the toggle control that switches it and calls the view-mode endpoint.

**10. Sort Control** - Build the sort dropdown and wire it to re-fetch the video list with the chosen sort.

**11. Rename and Description Editing** - Build the inline title editor and the description-edit modal, including the client-side and server-inline-error paths for an empty title.

**12. Delete Confirmation Flow** - Build the delete confirmation modal, including the 1-second disabled state on its Delete button, and remove the deleted video from the displayed list on success.

**13. Empty Library State** - Build the empty-state illustration and message, shown in place of the video list when the library has zero videos, alongside the existing upload drop zone.

**14. Compose the Real Library Page** - Replace F03's placeholder `VideoLibrary` composition in `apps/web/app/app/page.tsx` with the full library experience: initial view mode and sort read from the user's profile, the toggle, the sort control, the context menu, and the three modals.

### Stage 4: Verification

**15. Automated Test Coverage** - Write the backend unit and integration tests (value objects, use cases with fakes, extended route tests) and the frontend unit/component tests, per the spec's Testing Strategy.

**16. End-to-End Coverage** - Write the Playwright spec covering rename persistence, delete persistence, and view-mode persistence across a logout/login cycle, against the real backend.
